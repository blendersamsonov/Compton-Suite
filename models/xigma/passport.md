## 0. Краткое резюме

```text
Код/метод: XIGMA-I
Основная расчетная задача: вычисление числа фотонов, энергетического спектра и спектрально-углового распределения при обратном комптоновском рассеянии лазерного импульса на электронном сгустке.
Тип метода: табулированное 4D-перекрытие фазового пространства (H[γ, θx, θy, a0], построенное депозицией реальных макрочастиц) + аналитическая дельта-функция резонанса, свёрнутая в 3D-квадратуру (θx, θy, a0) по кольцевым/дуговым ячейкам детектора.

Текущий статус: рабочий исследовательский код после завершённой миграции на табулированный конвейер (Stage 0-2); старый аналитический путь (core.py/core_cpu.py) полностью удалён. GUI-интеграция (полный набор наблюдаемых) готова.
Текущий уровень доверия: C (технически работает, взаимно проверено тремя независимыми методами и CPU/GPU-путями, но нет unit-тестов, нет сравнения с внешним кодом/экспериментом, есть один зафиксированный, но не устранённый источник шума).
Что нужно сделать для первого сравнения: зафиксировать один эталонный конфиг (см. §9), провести систематическое сканирование сходимости (инструменты есть, прогонов нет), сравнить с независимым кодом или опубликованным результатом.
```

## 4. Физическая модель и приближения

### 4.1. Основная физическая модель

```text
Код вычисляет число фотонов обратного комптоновского рассеяния, заменяя однoэлектронную
резонансную функцию дельта-функцией — это позволяет аналитически свернуть интеграл по
энергии электронов в 4-мерную таблицу перекрытия фазового пространства
H[γ, θx, θy, a0], которая строится прямой депозицией реальных макрочастиц (Stage 0/1),
без предположения о факторизуемости и гауссовости распределения электронов по энергии.

Итоговый спектр в точке (θx, θy, s) получается сверткой H с резонансным префактором
(eq. "main"/"Fmatrix" сопроводительного paper, coef = 1.5) через кольцевую/дуговую
квадратуру по детектору с обратно-CDF импортанс-сэмплингом по φ и билинейной/
квадрилинейной интерполяцией H (Stage 2, `spectrum_kernel_4d`).

Параметр a0 (4-я ось H) — это не мгновенная локальная напряжённость поля, а
траекторно-усреднённый эффективный a0 (`ahat`), вычисленный из интеграла
∫a0_local(t)^2 dt по всей траектории электрона (eq. "ahattraj"); он входит в резонансное
условие и в множитель 1/(1+a0) в префакторе. Это реальная физическая величина —
не феноменологическая поправка, в отличие от предыдущей версии кода (см. §4.3).
```

### 4.2. Как устроен расчет

```text
Stage 0 (particles.py). Электронный сгусток сэмплируется вызывающей
стороной через compton_io.bunch.sample_gaussian_bunch (единственное место
сэмплирования сгустка на весь проект) и конвертируется в формат этого
пакета функцией bunch_from_macrobunch, которая даёт реальные per-particle
(x0, y0, z0, γ, θx, θy). push_and_sample баллистически проталкивает каждую частицу через импульс и для каждой
частицы (не на каждом шаге!) выдаёт одну строку (γ, θx, θy, a0, weight): γ/θx/θy
постоянны вдоль прямолинейной траектории, weight — интеграл люминесцентности
L(ζ) = Σ v_rel * n_ph * dt * weight_макро по траектории, a0 — траекторно-усреднённый
ahat (или его a0-независимый "shape"-аналог, см. ниже). n_steps задаёт разрешение
внутреннего временного интегрирования, а не число выходных строк (оно всегда равно
числу частиц).

Stage 1 (deposition.py). deposit_nearest/deposit_cic депонируют
(γ, θx, θy, a0, weight) в 4D-сетку H scatter-add'ом (bincount на CPU,
cupyx scatter_add на GPU), с поддержкой потокового построения таблицы
(build_table_streaming) для сгустков, не помещающихся в память целиком.

a0 факторизуется точно: a0_local(t)^2 = compton.a0^2 * ratio(t), где ratio(t) зависит
только от (a0-независимой) траектории. Поэтому push_and_sample сразу отдаёт
a0-независимый "shape"-профиль, а retarget_a0(table, a0) конвертирует его в
физическую, готовую к расчёту спектра таблицу ('ahat') для конкретного a0 дешёвым
консервативным (mass-preserving) ребиннингом — без повторного прогона Stage 0/1 при
смене энергии импульса.

Stage 2 (spectrum4d.py). spectrum_kernel_4d — основной GPU-путь; численно проверенный
CPU/numba-фолбэк spectrum4d_cpu.py используется автоматически при отсутствии GPU.
Три независимых способа расчёта спектра без доверия к этому ядру собраны в
reference.py (см. §8).
```

### 4.3. Основные приближения

```text
1. Однoэлектронная резонансная функция заменена дельта-функцией (аналитическое
   упрощение, лежащее в основе табличного подхода H).
2. Слабо-нелинейный режим (a0 ≲ a0_max, по умолчанию 0.5) — a0 теперь реальная ось
   таблицы (physical ahat), а не феноменологическая поправка; вне этого диапазона
   модель не валидна (см. §6).
3. Ультрарелятивистский предел (γ >> 1) для связи энергии и угла рассеяния.
4. Гауссовы профили электронного сгустка (в координатах и по энергии, с поддержкой
   произвольных корреляций γ-θ и чирпа при сэмплировании) и лазерного импульса
   (поперечный профиль TEM00, продольная огибающая гауссова).
5. Параксиальное приближение для лазерного пучка.
6. Баллистическое движение электронов — отсутствие обратного влияния излучения на
   динамику (радиационное трение не учитывается).
7. Столкновение только "в лоб" (crossing_angle = 0) — угол встречи не поддерживается
   архитектурно, не только не реализован.
8. Пренебрежение многократным рассеянием.
```

### 4.4. Что принципиально не входит в модель

```text
1. Излучение на гармониках / сильно-нелинейный режим (a0 > 1).
2. Отдача/множественное рассеяние.
3. Угол встречи пучков (crossing angle) — не архитектурная опция для доработки, а
   осознанное ограничение текущей модели.
```

## 6. Область применимости

### 6.1. Проверенные режимы

```text
1. Линейный режим (a0 → 0): три независимых метода расчёта спектра согласуются
   в пределах ~15% на типовой конфигурации сгустка (см. §8).
2. Слабо-нелинейный режим (a0 ≲ a0_max = 0.5 по умолчанию) — та же проверка.
3. Эллиптические электронные пучки (sigma_ex != sigma_ey), астигматические пучки
   (emittance_x != emittance_y), произвольные корреляции по фазовому пространству
   (чирп, angle-energy) — поддерживаются архитектурно (табличный подход не требует
   факторизуемости распределения), отдельно не верифицированы.
```

### 6.2. Режимы, требующие проверки

```text
1. Узкоугловые / sparse-table конфигурации: spectrum_kernel_4d показывает большую
   нестабильную дисперсию (превышение над двумя другими reference-методами в
   ~3-30 раз в зависимости от числа частиц/разрешения таблицы) — похоже на шум
   импортанс-сэмплинга по разреженным/нулевым ячейкам H, а не на ошибку нормировки;
   зафиксировано, но не устранено.
2. Систематическое сканирование сходимости по разрешению сетки/числу частиц/
   квадратуре — инструменты есть (см. CLAUDE.md "Convergence testing"), прогонов
   не проводилось.
3. Смещение фокусов (delta_x, delta_y, delta_z ≠ 0).
```

### 6.3. Режимы, где код не следует использовать без доработки

```text
1. Сильные поля (a0 > 1, вне a0_max), где доминирует нелинейное комптоновское
   рассеяние и генерация гармоник — вне модели по построению (см. §4.4).
2. Угол встречи пучков (crossing_angle ≠ 0) — не поддерживается архитектурно.
3. Область параметров, где энергия фотонов сравнима с энергией электронов (глубокий
   квантовый режим) — формула сечения некорректна.
```

## 8. Проверка кода

### 8.1. Верификация

| Проверка | Статус | Комментарий |
|---|---|---|
| Сравнение с аналитическим пределом | не зафиксировано | Аналитическая оценка выхода есть (`Compton.estimate_yield`), но систематическое сравнение отсутствует. |
| Проверка нормировки | частично | `coef = 1.5` в `spectrum_kernel_4d`/`spectrum_from_table` выведен из eq. | Проверка сходимости | не зафиксировано | Инструменты есть (см. CLAUDE.md "Convergence testing"), систематических прогонов не проводилось. |

## 10. Текущий статус и ближайшие шаги

### 10.1. Что уже работает

```text
1. Stage 0 (compton_io.bunch.sample_gaussian_bunch + particles.bunch_from_macrobunch/push_and_sample) — сэмплирование сгустка и баллистический
   толкатель, с траекторно-усреднённым a0 (ahat) и a0-независимым "shape"-профилем
   (retarget_a0 для дешёвой смены энергии импульса без пересчёта частиц).
2. Stage 1 (deposition.py) — депозиция nearest/CIC в 4D-таблицу H, CPU и GPU,
   потоковое построение для больших сгустков (build_table_streaming).
3. Stage 2 (spectrum4d.py) — расчёт спектрально-углового распределения на GPU
   (spectrum_kernel_4d) с численно проверенным CPU/numba-фолбэком
   (spectrum4d_cpu.py), включая временную огибающую и пространственное
   распределение излучения (PushDiagnostics).
4. Три независимых reference-пути (reference.py) для проверки Stage 2 без доверия
   к самому ядру: angle_integrated_spectrum, spectrum_from_table,
   direct_binning_spectrum.
5. Полная GUI-интеграция (gui_adapter.py, TabulatedEngine) — все наблюдаемые
   (полный выход, энергетический спектр, угловое и спектрально-угловое
   распределение, временная огибающая, пространственное распределение) идут
   через один прогон Stage 0-2, greyed-out деградация без CUDA/cupy.
6. Легаси-путь (core.py/core_cpu.py, феноменологическая эмуляция нелинейности)
   полностью удалён — в репозитории нет других расчётных путей.
```

Краткий комментарий:

```text
После завершения миграции на табулированный конвейер (Stage 0-2) код выполняется на
NVidia GPU и, автоматически, на CPU (numba-фолбэк, численно проверен против GPU-ядра),
и даёт физически правдоподобные результаты, взаимно согласованные тремя независимыми

прежнее разделение уровня доверия на линейный/нелинейный режим (единый рейтинг C).
Тем не менее отсутствуют unit-тесты, фиксированный эталонный конфиг, систематическое
сканирование сходимости и сравнение с внешним кодом или экспериментом — использовать
для валидированных расчётов без дополнительной проверки нельзя. Отдельно зафиксирован
(не устранён) источник большой нестабильной дисперсии spectrum_kernel_4d в
узкоугловых/sparse-table конфигурациях (§6.2, §8.3).
```
